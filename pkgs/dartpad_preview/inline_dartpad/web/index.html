Inline DartPad

Every code block on this page is a <pre data-dartpad-filename> element that inline_dartpad.js upgrades in place: an editor with diagnostics, hover and completion, a run button and a console. No <iframe> per sample; all pads on this origin share one SharedWorker, all pads on a page share one language server, and code runs in sandboxed <iframe>s nobody sees.

Edit any example and press Run or Ctrl+Enter. Hover a symbol for documentation, type to get completions, and Reset appears once you have changed something. The bar above switches between the themes in themes.css:

How to use it

Include the stylesheet and the script once per page:

<link rel="stylesheet" href="inline_dartpad.css">
<script src="inline_dartpad.js" defer></script>

Then write code blocks as usual, with a data-dartpad-filename attribute. Markdown renderers produce exactly this shape, so a fenced code block with the right attributes is enough: 

<pre data-dartpad-filename="hello.dart" data-dartpad-preview="start"><code>
void main() {
  print('Hello, world!');
}
</code></pre>
attributevaluesdefault
data-dartpad-filenamea file name; marks the block as a padrequired
data-dartpad-previewstart runs when scrolled into view, pause waits for the run button, none is just an editorpause
data-dartpad-layoutvertical console below the editor, horizontal to the right of itvertical
data-dartpad-outputtext shown in the console until the program runs

Only dart: libraries are available, there is no pub.dev. Everything is static files served next to inline_dartpad.js: shared-worker.js and the DartPad SDK assets in dartpad/dart/ (both on the page's origin), relocatable with data-worker and data-sdk on the <script>.

Examples

Hello world preview="start"

Runs by itself the first time it scrolls into view.

void main() {
  print('Hello, world!');
}

String interpolation preview="pause"

The default: an editor, a run button and an empty console waiting for you.

void main() {
  final name = 'Dart';
  final version = 3.14;
  print('Hello from $name ${version.toStringAsFixed(1)}!');
  print('${name.toUpperCase()} has ${name.length} letters.');
}

Just an editor preview="none"

Analysis only: diagnostics, hover and completion, but nothing to run.

abstract class Shape {
  double get area;
}

class Circle implements Shape {
  Circle(this.radius);
  final double radius;

  @override
  double get area => 3.14159 * radius * radius;
}

Async Future<void> main()

Output arrives as the program produces it.

Future<void> main() async {
  for (var i = 3; i > 0; i--) {
    print('$i...');
    await Future<void>.delayed(const Duration(milliseconds: 400));
  }
  print('Liftoff! 🚀');
}

Collections and records preview="start"

void main() {
  final numbers = [for (var i = 1; i <= 5; i++) i * i];
  final (min, max) = (numbers.first, numbers.last);
  print('squares: $numbers, min: $min, max: $max');

  final byParity = {
    for (final n in numbers) n.isEven ? 'even' : 'odd': n,
  };
  print(byParity);
}

A compile error the compiler log goes to the console

void main() {
  int count = 'not a number';
  print(count);
}

A runtime error uncaught errors are reported too

void main() {
  final list = <int>[];
  print('About to fail...');
  print(list.first);
}

Classes preview="start"

class Point {
  const Point(this.x, this.y);
  final double x, y;

  Point operator +(Point other) => Point(x + other.x, y + other.y);

  @override
  String toString() => 'Point($x, $y)';
}

void main() {
  const origin = Point(0, 0);
  final p = origin + const Point(2, 3) + const Point(1, 1);
  print(p);
}

Customizing the theme

inline_dartpad.css ships the look of dart.dev's code blocks, in light and dark. Pads follow prefers-color-scheme, unless a dartpad-light or dartpad-dark class on an ancestor (<html>, typically) picks a palette, which is how the Dark mode button above works: 

<html class="dartpad-dark">

Everything else is a --inline-dartpad-* custom property, set on any ancestor. The full list, with the default values, is at the top of inline_dartpad.css:

propertywhat it is
--inline-dartpad-font-ui, -font-mono, -font-sizefonts for the buttons, and for code and console; the base font size
--inline-dartpad-radius, -border, -shadowthe box around the pad
--inline-dartpad-line-numbersnone or flex, the line-number gutter
--inline-dartpad-editor-bg, -editor-fg, -gutter-fg, -selection, -active-linethe editor
--inline-dartpad-console-bg, -console-fg, -console-muted, -console-errorthe console, the status line and error output
--inline-dartpad-accent, -accent-fgthe run button
--inline-dartpad-popup-bg, -popup-fgcompletion and hover popups
--inline-dartpad-cm-keyword, -cm-string, -cm-comment, …syntax highlighting, one per CodeMirror token type

For example, rounder pads with line numbers and a different accent, in one part of a site:

.my-docs .inline-dartpad {
  --inline-dartpad-radius: 1rem;
  --inline-dartpad-line-numbers: flex;
  --inline-dartpad-accent: #0d47a1;
}

For anything beyond colors and metrics, the DOM is small and stable, and the root element carries the pad's state as attributes, so a theme is ordinary CSS: 

.inline-dartpad[data-layout][data-preview][data-state=idle|running][data-modified]
  .inline-dartpad-editor   > .cm-editor
  .inline-dartpad-output   > .inline-dartpad-status + .inline-dartpad-console
  .inline-dartpad-controls > .inline-dartpad-filename + .inline-dartpad-reset + .inline-dartpad-run

The eight themes in the bar above are built exactly like that, as .idp-theme-* classes in themes.css; copy the one you like into your own stylesheet.
